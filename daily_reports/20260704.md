## Interpretation

- `Submission Format Error` appears in the Kaggle UI even when the API reports `COMPLETE` with blank public score.
- For this repo's records, treat these as hosted-evaluation failures rather than successful zero-score runs.
- The recent failures share pressure around candidate count, message count, or live probing. `v053` shows a lower-count static shape can still succeed, but it does not beat `v043`.
- `jed-indirect-marker` is a new direction: it does not directly ask for `http.post`, but asks the model to open public fixture pages `mh_web_sink_1` / `mh_web_hop_3` and follow remediation notes.
- `v056` / `v057` avoid attack-generation runtime and long prompt chains. The remaining risks are hosted replay/evaluator boundary and public-notebook transfer sensitivity.
- `jed-indirect-marker` did not transfer through our script-kernel wrapper and ended as `Submission Format Error`; do not continue that branch without a wrapper-level reason.
- `attack-single-900` is closer to our prior `v055`, but the public-scoring variant uses `.invalid`, the shorter no-comma prompt, and the slowest steady latency probe. Exact transfer should be tested before hybridizing.
- For this competition, Kaggle code submissions should use `-f submission.csv`; `attack.py` must still be generated in the kernel output.
