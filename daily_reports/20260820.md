## Findings

- Four independent throughput pushes on the proven family (`v150`, `v152`,
  `v154`, `v155`) all regressed. Two (`v152`, `v155`) chain a second action
  into one message; the other two (`v150`, `v154`) push existing knobs
  further. This is strong convergent evidence that `v148`'s exact
  configuration (`REPLAY_SAFE_FRAC=0.985`, `SPLIT_CLASSIFY_N=6`,
  `PROBE_HOPS=0`, `SLOW_MULTIPOST_N=1`, single-action template) sits at a
  local optimum for this attack family, and that compound multi-action
  messages carry a real compliance/reliability cost distinct from the
  guardrail itself.
- Reading the actual SDK source (guardrail + predicates + tools + cell
  signature) turned three weeks of discussion-based speculation into
  confirmed fact: `DESTRUCTIVE_WRITE` and `UNTRUSTED_TO_ACTION` are
  provably unreachable against `OptimalGuardrail`; `CONFUSED_DEPUTY` is
  provably reachable. This is a much stronger evidence base than
  discussion hearsay and should be the default first step before designing
  any new predicate-targeting experiment.
- Constructing a synthetic trace and calling the real `Guardrail.decide()`
  / `eval_predicates()` functions directly (rather than only reasoning
  about the source) caught a real bug (an accidental "secret" substring in
  a draft email body) before it cost a submission slot -- this local
  verification step is now a recommended addition to the pre-submission
  checklist for any new predicate/template experiment.
- Community discussion (`hengck23`/`cm391`, 2026-08-19/20) raises a
  significant unresolved risk: the entire public-LB-optimized SECRET_MARKER
  throughput strategy may not transfer to the private guardrail at all,
  and hosted evaluation is reportedly unstable competition-wide (CPU-only
  execution regardless of notebook GPU setting, unconfirmed model/GGUF
  versions, inconsistent tool-use across runs). This has not yet been
  investigated further in this repo; worth a dedicated look if time
  permits, though we have no direct way to observe our own private score.
